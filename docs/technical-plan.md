# 技术路线与阶段计划

状态：可执行计划草案，不代表运行验证已完成。

## 拟选路线

标准 Cubism 模型为主要交付格式，兼顾 P2G 与 VTube Studio。Inochi2D 可以研究，但其开放格式并不直接兼容 P2G 当前标准 Live2D 导入要求，因此暂不作为主线。

自动拆层与绑定只作为生产辅助。对 eyes/mouth/face turn 等关键部位，以实际形变结果决定是否使用自动结果，不以项目宣传或能够导出文件作为成品质量依据。

独立 AI 伴侣将 AIRI 作为首选验证对象，Open-LLM-VTuber 作为后备。AIRI 的表情工具、动作驱动与桌面 MCP 实现较符合可扩展需求；接入现有 Q 语音兼容接口，云端语音备选 Step Token Plan，聊天使用 DeepSeek。接口类型已确认，最终兼容性依赖样例运行结果。详见 [AIRI 源码评估](airi-review.md)与[语音接入计划](speech-and-llm.md)。

## 共同角色接口

规划用稳定的表情语义和动作名连接不同使用端。例如 normal、confused、happy、pout、wink、smile；语音播放状态与音频幅度负责嘴部驱动，情绪负责表情与动作选择。

AI、待机、预设动作、面捕可能同时控制相同参数，需要明确优先级和过渡规则。P2G 通过其已有映射适配；独立程序通过受控事件驱动。具体字段及代码尚未编写。

换装先按独立服装部件与资源规范预留。若 P2G 不能暴露实时换装控制，可以生成每套服装一个独立模型 ZIP；是否能在同一角色内直接换装需验证，不能仅凭 Cubism 能力保证宿主也支持。

## P2G 只读检查发现

检查对象：用户安装的 Steam Windows 版，2026-09-11。

- Electron 应用内包含 Pixi、Cubism Web 渲染模块与 Cubism Core。
- 创建角色界面存在启用状态为禁用的 Live2D 选项，并显示维护文案；用户也确认界面不可用。
- preload 桥接仍提供 `desktopCharacters.importLive2D`，后台仍注册对应导入处理逻辑。
- 导入器验证 ZIP 路径、文件类型、数量、大小与资源完整性，并要求恰好一个 `.model3.json`。
- 导入器仍能整理动作、表情预设并返回本地模型资源 URL；角色持久化接口仍存在。
- 渲染代码包含情绪到动作/表情映射、音频驱动嘴部开合及 30 FPS 上限。

**推断**：有机会通过现有本地导入桥接和角色保存流程完成适配。尚未实际调用、改动程序或导入样例，不排除维护背后的运行问题。

后续首先在可回退条件下验证原有桥接与本地资源加载，不移除 ZIP 校验。若需要界面适配，将按已验证版本提供最小改动和回退步骤；若流程失效，整理错误与复现信息供用户联系开发者。

公共仓库不保存完整游戏程序、解包的游戏代码或用户角色数据库，只保存本项目的适配说明与后续原创实现。

## 阶段顺序

### P0：规划收敛（当前）

确定需求，检查参考视频与程序，收集框架资料，确认 LLM/TTS 接口类型。尚未制作角色或修改 P2G。

### P1：技术验证

采用适当的已有样例验证 Cubism 加载、P2G 导入、持久化、情绪与口型。与此同时验证独立聊天程序能调用一个现有 TTS。记录实际能力与限制，再确定正式交付格式。

通过条件：重启后模型可用；语音嘴部和表情互不冲突；有明确回退路径。

### P2：大月下默认服饰设计与分层

从官方外观参考形成适合绑定的全身站姿立绘，审阅脸与服饰后拆层。眼睛、眉毛、嘴部、发束、饰品和服装遮挡按所需形变设计并补全。

通过条件：用户认可外观；关键层有充分遮挡补绘和后续编辑空间。

### P3：绑定与表演

面部方向与交叉形变、独立眨眼、目光、眉毛、嘴部、呼吸、身体跟随、头发和衣装物理；制作六种核心表情及配套动作。

通过条件：极值和组合姿态无明显破图，表情与说话可叠加，待机自然。

### P4：三端接入与交付

打包 P2G 资源、独立 AI 配置和 VTube Studio 摄像头配置，验证实际加载及播放；交付可编辑素材和再制作说明。

### P5：常服扩展

先核验参考出处并由用户审阅，再制作服装层及物理，验证原有表情和驱动复用。服装是否可在 P2G 内直接切换依据 P1/P4 结果实现。

### P6：小格蕾修

复用已验证流程与通用驱动，重新制作适合小格蕾修体型、五官、服饰和角色表现的美术与绑定。
